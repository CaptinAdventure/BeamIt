# BeamIt macOS client: clipboard transfers

The app project is `BeamIt/BeamIt.xcodeproj`. General connection, streaming
and input instructions are in the [main README](../../README.md). Clipboard
production integration is authored, but native Mac compilation/runtime and
LAN validation are **UNAVAILABLE on the Windows development machine**.
The commands below are provided for Mac verification, not reported passes.

## Use clipboard synchronization

Connect using the host certificate fingerprint. Enable **Clipboard Sync**,
or use **Sync Host to macOS** / **Sync macOS to Host** manually while BeamIt
is active. Manual commands work with automatic sync disabled.

Both directions support text, HTML, transparent PNG and multiple regular
files/folders, including nested, empty and hidden entries. Cmd+V in normal
stream input mode waits for host publication and rechecks the same window,
focus and local clipboard count before sending paste. Captured physical
keyboard behavior remains unchanged. Decline, Cancel, failure or stale state
must not paste old content.

Automatic bulk transfer requires **regular-file bytes < 500,000,000 AND
selected roots <= 5**. Each selected folder is one root; all descendant
regular-file bytes count. Reaching the byte threshold or selecting six roots
requires **Transfer** / **Cancel** confirmation before payload. Changed
source metadata invalidates the spool and previous confirmation. The
nonactivating progress panel includes Cancel for automatic transfers too.
Success waits for receiver publication, not the last socket write.

Configure integer UserDefaults keys `clipboardBulkByteThreshold`
(0–2,000,000,000) and `clipboardBulkEntryThreshold` (0–64) in the app's actual
bundle domain. The project generates a per-project bundle identifier; read
`CFBundleIdentifier` from the built app's `Info.plist`, rather than assuming
a fixed domain. For example, after assigning that identifier to `BUNDLE_ID`:

```sh
defaults write "$BUNDLE_ID" clipboardBulkByteThreshold -int 500000000
defaults write "$BUNDLE_ID" clipboardBulkEntryThreshold -int 5
```

Invalid values produce diagnostics and use 500,000,000/5. These preferences
do not increase hard limits or add app CLI options/settings UI.
Concealed clipboard content is not automatically pushed. An explicit
paste/manual upload retains its sensitive-host-write marker. Excluded host
content and transient/autogenerated local content are not mirrored.

## Storage, safety and compatibility

The client negotiates optional bulk version 1 after existing protocol-1
authentication. Only an old host's `unknown_type` permits fallback to legacy
text/HTML/base64-PNG; files are unavailable in that mode.
The client always opens the pinned, same-authority bulk WSS socket.
Disk enumeration, hashing, spool/staging and PNG conversion run on a storage
actor, not MainActor. Frames drain serially before verified END/publication.
UI/pasteboard operations stay on MainActor.

The [main Clipboard section](../../README.md#clipboard) defines hard limits:
2,000,000,000 regular-file bytes, 64 roots, 4,096 nodes, 4 MiB manifest,
255-byte components, 4,096-byte relative paths; PNG separately 64 MiB encoded,
16,384 pixels per side, 64 Mpixel. Unsafe/colliding names, symbolic links,
special/unreadable files and file promises are rejected. There is no resume,
cut/move or metadata/ACL replication.

Private staging is
`~/Library/Application Support/BeamIt/ClipboardStaging`, with an
8,000,000,000-byte shared quota including unmaterialized reservations and
128 MiB scratch per operation. Descriptor-relative no-follow opens, private
permissions and a cross-process lock/kernel lease ledger protect staging.
`~` here is the app's home: the sandboxed build normally places it beneath
`~/Library/Containers/<bundle-id>/Data`, not the user's unrestricted home.
Staging traversal starts at that container home because the sandbox may deny
opening its ancestors; descendants are still opened without following symlinks.
Native pasteboard URL reads obtain user-selected access; security-scoped
access is balanced for the lifetime of the captured source.
Live owners survive recovery; outgoing/failed partial work is cleaned.
**Published `client/committed` files are never automatically deleted.**
Stop transfers, clear the pasteboard and close all consuming applications
before manually removing unneeded committed selections. Do not remove live
ledgers, partials or outgoing directories. Retain anything whose consumers
are uncertain.

macOS has no atomic transaction for arbitrary third-party delayed
pasteboard formats. The client prepares supported formats, captures supported
old representations, checks the destination again, then writes the complete
selection. A failed write attempts supported-format rollback, reports the
limitation and sends no success acknowledgement. If rollback cannot prove
new file references are gone, it conservatively retains their files.

## Focused checks on a Mac

Use the Xcode/macOS SDK required by the existing project (deployment target
macOS 27). Its filesystem-synchronized app group automatically includes
`BeamItClipboardBulk.swift` and `BeamItClipboardStorage.swift`.
There is no shared XCTest target/scheme in this project. From repository
root, build the actual application target:

```sh
xcodebuild -project clients/osx/BeamIt/BeamIt.xcodeproj -target BeamIt \
  -configuration Debug -sdk macosx CODE_SIGNING_ALLOWED=NO \
  SYMROOT="$TMPDIR/BeamIt-ClipboardBuild/Products" \
  OBJROOT="$TMPDIR/BeamIt-ClipboardBuild/Intermediates" build
```

Run standalone checks with Swift 6.2 or newer. Do not use optimization that
disables `precondition` checks:

```sh
test_dir="$(mktemp -d -t beamit-clipboard-tests)"
xcrun swiftc -swift-version 6 -default-isolation MainActor -parse-as-library \
  clients/osx/BeamIt/BeamIt/BeamItClipboardBulk.swift \
  clients/osx/BeamIt/Tests/ClipboardBulkTests.swift \
  -o "$test_dir/ClipboardBulkTests"
"$test_dir/ClipboardBulkTests"

xcrun swiftc -swift-version 6 -default-isolation MainActor -parse-as-library \
  clients/osx/BeamIt/BeamIt/BeamItClipboardBulk.swift \
  clients/osx/BeamIt/BeamIt/BeamItClipboardStorage.swift \
  clients/osx/BeamIt/Tests/ClipboardStorageTests.swift \
  -framework CryptoKit -framework Security -framework ImageIO \
  -framework UniformTypeIdentifiers -o "$test_dir/ClipboardStorageTests"
"$test_dir/ClipboardStorageTests"
```

The storage executable uses private temporary fixtures, a sparse logical
quota fixture and injected storage roots. It never opens the real pasteboard.
It covers multi-chunk folder/empty/hidden/zero-byte content, hashes,
preliminary/final JSON, early/duplicate END, promotion-before-END rejection,
source identity drift, symlink rejection, unpublished cleanup, committed
retention, live-owner quota protection, abandoned recovery, PNG decode and
dimension mismatch. The pure checks cover framing, malformed fields/paths,
threshold/settings boundaries and canonical IDs.

### Native/LAN procedure — NOT RUN

Use disposable copied files and an isolated test host:

1. In both directions, paste text/HTML into a rich-text app, PNG with alpha
   into an image app, and multiple file/folder roots into Finder/Explorer.
   Verify nested, empty, hidden and Unicode entries and unchanged sources.
2. Verify five roots and 499,999,999 bytes are automatic; six roots and
   exactly 500,000,000 bytes prompt. Decline before payload; repeat with
   Transfer and Cancel. Change a source during preparation and verify a new
   confirmation. Smaller configured thresholds can exercise UI cheaply, but
   do not replace exact-default boundary checks.
3. During preparation, transfer and publication, change the destination
   pasteboard, local source or focused stream; deactivate BeamIt and disable
   sync. Verify no stale publication or old-content paste. Test Cmd+V after
   an already-acknowledged upload and then a host clipboard change.
4. Disconnect during payload and after END; reconnect and restart with a new
   ID. Verify receiver acknowledgement, not socket closure, controls success.
   Exercise old-host fallback and exclusion/sensitive behavior.
5. Hold destination pasteboard ownership or inject native API failure. Check
   explicit failure/rollback disclosure and no partial file list. Replace
   the pasteboard after success and verify consumers retain usable files.
6. During a representative large transfer, record control/input latency,
   video behavior and progress/cancel responsiveness. Native UI, rollback,
   app paste, cross-machine LAN and sustained performance require actual
   Mac/Windows execution; Windows mocks are not substitutes.
